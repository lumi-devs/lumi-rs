# agents/03-db.md

## Hard rule — NO RAW SQL outside crates/db

Modules, UI, script, and the bin crate MUST NEVER contain raw SQL strings.
No `Statement::from_*`, `execute_raw`, `query_all_raw`, `query_one_raw`,
`sea_query` string SQL, or any literal SQL text.

Use:
1. SeaORM 2.0 typed queries (entities + `Entity::find()`, `ActiveModel`, etc.)
2. Typed helpers in `crates/db/src/` (e.g. `db::next_counter`)

If the ORM genuinely can't express something, add a helper in `crates/db/src/`
with a doc comment explaining why raw SQL was needed. That's the only place.

## Entities

All entities live in `crates/db/src/entities/`. Each is a standard SeaORM
derived entity:

```rust
#[sea_orm::model]
#[derive(Clone, Debug, PartialEq, Eq, DeriveEntityModel)]
#[sea_orm(table_name = "my_table")]
pub struct Model { … }
impl ActiveModelBehavior for ActiveModel {}
```

Register it in `crates/db/src/entities/mod.rs`. The baseline migration
(`m0001_baseline`) schema-syncs from the entity registry — no hand-written
`CREATE TABLE` needed for new entities.

## Migrations

`crates/db/src/migrations/`. Add a new file `mNNNN_<desc>.rs` for schema
changes after the baseline (indexes, renames, column adds). Keep one logical
change per migration. Register in `Migrator`.

## Helpers

`crates/db/src/lib.rs` exposes:
- `db::connect(url) -> Result<DatabaseConnection>`
- `db::migrate(db) -> Result<()>`
- `db::next_counter(db, guild_id, name) -> Result<i64>` — atomic per-guild
  counter (e.g. moderation case numbers), implemented with `FOR UPDATE` txn.

Add new helpers here when modules need DB operations the ORM can't express
cleanly in a single call.

## for_guild pattern

Design all DB calls as `db.for_guild(guild_id)` from day one — today it
returns the one pool, later it routes to a PG shard with no refactor.
Keep `guild_id` leading in every composite index.
Create guild rows lazily (only on first activity), never eagerly.
